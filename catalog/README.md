# catalog/ —— 工具记录（「目录」）

**这里放的是「有哪些工具」这件事本身**：名字、描述、分类、图标、链接、点赞数。
一个 `.json` 文件一条记录。

它**不是**工具本体。工具本体（解压后的开源项目）在 `../tools/` 下，见那份 README。
一句话分清楚：**`catalog/` 是货架上的标签，`tools/` 是货。**

```
catalog/ppt.json        一个工具一条
catalog/_template.json  模板；`_` 与 `.` 开头的文件会被跳过，不会被当成工具收录
```

---

## 一、和谁配合

```
catalog/*.json
   │  读盘（每个请求重新读一次，不缓存）
   ▼
data-service/adapters/json-dir.js        ← DATA_SOURCE=json-dir（默认）
   │  「读出来 → 交给语义层」
   ▼
data-service/core/memory-adapter.js      ← 语义基准：归一化 / 过滤 / 排序 / 分页
   ▼
GET /api/tools  /api/tags  /api/hot      ← 数据服务 :3001
   ▼
assets/js/api.js → views.js              ← 页面据此画卡片
```

这个目录是 **`DATA_SOURCE=json-dir` 的 `DATA_DIR`**。默认值写在
`../data-service/adapters/json-dir.js` 的 `DEFAULT_DIR`（源码里用 ★ 标出来了，
搜 `★` 就能找到），环境变量 `DATA_DIR` 优先级高于它。
也就是说它是「数据源」那层的一个可替换零件 —— 换成 MySQL 时，这个目录不再被读，
但页面和静态服务一行都不用改。见 `../docs/adapters.md`。

## 二、一条记录长什么样

```json
{
  "id": "ppt",
  "name": "PPT生成",
  "description": "根据主题快速生成演示文稿，适合汇报、课件和提案。",
  "tags": ["演示文稿", "办公"],
  "icon": "📊",
  "url": "/tools/ppt/",
  "enabled": true,
  "likes": 0,
  "order": 1000
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | **是** | 唯一标识。**以文件里的这个字段为准，不是文件名**；两者不一致会打一条警告 |
| `name` | string | **是** | 工具名称 |
| `description` | string | 否 | 一句话描述 |
| `tags` | string[] | 否 | 分类标签，工具页的筛选条由全部启用记录的标签派生 |
| `icon` | string | 否 | 图标，emoji 即可；缺省由页面补 `◆` |
| `url` | string | 否 | 外链（http/https），或站内地址 `/tools/<项目名>/` 指向 `../tools/` 下的本地副本。**其它协议会被当成没有链接** |
| `enabled` | boolean | 否 | `false` 表示暂不展示。**筛选和计数都在服务端做，这个字段不会发给前端** |
| `likes` | number | 否 | 点赞数，非负整数，缺省 0。**首页热门推荐的排序依据**；这个数同时画在卡片**右下角**（改完刷新就能看见，不用重启服务） |
| `order` | number | 否 | 排序键，越小越靠前，缺省 1000 |

字段与上限的完整定义在 `../docs/data-contract.md`，那是前后端唯一契约。

### `likes` 与 `order` 别搞混

- **`likes` 决定首页那 6 张热门卡是谁**（降序，同数按 `order`、`id`）
- **`order` 决定列表里的先后**（升序，同数按 `id`）

两个都必须有确定的次级键。点赞数会大量并列（尤其清一色的 0），
只按它排的话，同一批数据两次请求可能给出不同的 6 个 —— 而列表那边更严重：
排序不确定，**分页就会重复和漏项**（第 1 页和第 2 页之间只要有一条换了位置，
它要么出现两次，要么一次都不出现）。这就是 `order` 这个字段存在的全部理由。

### `likes` 目前只能由你手改

**没有「点一下 +1」的入口，也不该有**：两个服务除 `GET` / `HEAD` 外一律 `405`，
没有任何写入接口，服务端代码里也没有收请求体或写盘的代码。所以改点赞数的唯一办法
就是编辑这个文件，和改名字、改描述没有区别。

这是**有意不开放**，不是「还没来得及做」。将来做点赞是一套单独设计的东西
（谁能改、怎么防刷、要不要校验来源），在那套设计定下来之前不放宽任何一条 ——
见 `../Readme.md` 第八节「只读」。

## 三、加一个工具

1. 复制 `_template.json` 成 `<id>.json`，比如 `notion-ai.json`。
2. 改内容。`id` 和 `name` 必填，其余可省。
3. **不用重启任何服务**，刷新页面即可 —— 数据源每次请求都重新读这个目录。

删工具就是删文件，改工具就是改文件。`enabled: false` 是「先留着但不展示」。

如果这个工具**本体已经放在本地**了（`../tools/notion-ai/`），把 `url` 填成
`/tools/notion-ai/`；还没放就留空（卡片显示「即将上线」）或填外链。

## 四、会不会把服务搞挂

不会。**单条记录坏掉不会升级成整个接口 500**：

| 情形 | 结果 |
| --- | --- |
| JSON 语法错 / 不是对象 / 缺 `id` / 缺 `name` | 丢弃这一条，服务端打一条警告，其余照常返回 200 |
| `id` 与别的记录重复 | 丢掉后来的那条，警告一次 |
| `url` 不是 http/https 也不是站内 `/…` | **保留记录**，把 `url` 归一化成 `""` |
| `enabled: false` | 保留记录，但不进任何对外结果（列表、分类计数、热门都不算它） |

日志按消息去重，所以反复刷页面不会把日志刷满。

> **注意 `id` 改名等于换了一个工具**：`id` 是唯一标识，改了它，指向旧 id 的链接和
> 将来的点赞数据就对不上了。要改名的场合，请连同 `url` 一起检查。
