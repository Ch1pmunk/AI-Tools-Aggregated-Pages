# tools/ —— 本地工具本体（「货」）

**这里放解压后的开源项目本体**：去 GitHub download zip、解压、把整个目录放进这里，
放进去就等于这个工具有了本地副本，网页端可以直接打开它。

一个项目一个子目录，**目录名就是项目名**：

```
tools/
└─ ppt/                  ← 对应 catalog/ppt.json 里 url 填 "/tools/ppt/"
   ├─ index.html
   ├─ style.css
   └─ ...
```

目录里只有这份说明、还没有任何项目时，站点是**照常可用**的：卡片上会标出「本地副本未就位」，
点它只给一句提示，不会开一个注定是错误页的新窗口（见下第二节）。所以「还没放货」是一个正常状态，
不是一种要赶紧修掉的故障。

---

## 一、两个目录别再搞混

| | `../catalog/` | 这里 `tools/` |
| --- | --- | --- |
| 放什么 | 工具的**记录**：名字、描述、分类、图标、点赞数 | 工具的**本体**：项目文件 |
| 一条 = | 一个 `.json` | 一个目录 |
| 比喻 | 货架上的标签 | 货 |

两边的对应关系靠 **`catalog/<id>.json` 里的 `url` 字段**：填 `/tools/<项目名>/` 就指向这里。

---

## 二、点击卡片之后发生了什么

```
① 卡片渲染完（不是点击时）
   │  assets/js/views.js 的 probeLocalCards() 挨个探 url 是站内地址的卡片
   │  HEAD 一下 /tools/ppt/，结果记在卡片的 data-tool-local 上
   │   404 → missing（贴「本地副本未就位」角标）   超时/5xx/连不上 → unknown（什么都不标）
   ▼
② 用户点卡片
   │  assets/js/main.js 读出卡片上的 data-tool-url（同步，不 await）
   │  data-tool-local === 'missing' → 只给轻提示「还没有本地副本」，不开窗
   ▼
③ window.open('/tools/ppt/')
   ▼
④ server.js :3000  →  sendProject()
   │  ① 取出第一段当项目名（ppt）→ 必须落在 tools/ 之内（防 .. 穿越）
   │  ② tools/ppt/ 不在？  → 404「这个工具还没有本地副本」（专门的提示页）
   │  ③ 是目录但不带结尾斜杠？ → 302 补一个 / 再回来（否则项目页里的相对引用会解析错）
   │  ④ 请求目录 → 找它的 index.html（不出目录列表）
   │  ⑤ 扩展名必须在 PROJECT_MIME 白名单里
   ▼
项目文件发给浏览器，在本站源下运行
```

**第 ① 步和第 ④ 步的第 ② 条是两道，不是一道**，两道都要在：

- ① 是**提前拦一道**，图的是用户少开一个注定是错误页的新窗口。它**必然会漏**——探的时候不在、
  探完又放进去的，网络正好抖了一下的，都会漏过去。
- ④ 的 ② 是**兜底**，它永远对：每次请求都实时去看一眼目录在不在。地址是对的、只是货没到 →
  单独一页「这个工具还没有本地副本」，不跟「这里没有页面」混在一起。目录真放进去之后，
  这个提示自然就不再出现。

**① 里「探不到」不能当成「不在」**：只有明确收到 404 才算不在；超时、5xx、连不上都算「不知道」，
这时什么都不标、点击照旧打开，让第 ④ 步去给结论。把「没探到」说成「没有」，
就是在替服务端下结论 —— 和「0 条 vs 不知道有几条」是同一条道理（`../Readme.md` 第十二节）。

① 之所以在**渲染后**做而不是点击时做：点击必须同步开窗，中间插一次网络请求就会被浏览器
当弹窗拦掉（`../assets/README.md` 第三节）。

## 三、加一个本地工具

1. 下载项目的 zip，解压到 `tools/<项目名>/`，**确认里面有一份 `index.html`**
   （它是这个地址的入口；没有的话访问目录会 404）。
2. 在 `../catalog/` 下建 `<id>.json`，`url` 填 `/tools/<项目名>/`。
3. 刷新页面。卡片上会出现箭头，点开就是本地这份。

不用重启任何服务。

`url` 填 `/tools/xxx/` 时**结尾那个斜杠不能省**：项目页里 `style.css` 这类相对引用
以它所在目录为基准解析，少了斜杠就会指到上一级去。

## 四、安全边界（放之前请读）

- **`tools/` 下的 HTML / JS 是在本站源下执行的**，不是沙箱。
  这里放的项目能读到本站的公开接口、能操作它自己那个标签页。
  **只放你信得过的项目。**
- 静态服务只发这里面的**文件**，不发目录列表；扩展名不在白名单里的一律 404。
- `..` 与 `%2e%2e` 穿越在 `sendProject` 里被挡掉，解析结果必须落在 `tools/` 之内。
- 这个目录**不在** `/assets` 那张白名单里，走的是另一张（`PROJECT_MIME`），
  比前端资源那张宽 —— 因为这里放的是别人项目的成品，收得太紧会「文件明明在却打不开」，
  而且错得很安静（浏览器拿到 `octet-stream` 就白屏或直接下载）。

## 五、有意没做的事

这块目前**只做到「把已有的目录发给浏览器」**，仅此而已。以下都还没做，因为它们依赖
一个还没定的方案：

- 扫 `tools/` 自动生成 `catalog/` 记录（现在必须两边手动对齐，靠 `url` 字段牵起来）
- 每个项目里放一份清单文件（`tool.json` 之类）声明名字、描述、分类
- 按项目装依赖、起进程、做构建 —— 也就是「真的把项目跑起来」
- 点赞数的写入路径（现在 `likes` 是记录里的静态值，读得到、算得出热门，
  但没有「点一下 +1」的入口，也没有存的地方）。
  注意这是**有意不开放**，不是「还没来得及做」：两个服务除 `GET` / `HEAD` 外一律 `405`，
  没有任何写入接口（`../Readme.md` 第八节「只读」）

真要做的时候，起作用的是已经铺好的两条接缝：**数据侧的适配器**（`../docs/adapters.md`）
和**静态侧的这张白名单**（`server.js` 的 `sendProject`）。页面代码一行不用动。
