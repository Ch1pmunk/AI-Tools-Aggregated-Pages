# 结构

> `Readme.md` 是**需求**（这个站是什么），本目录是**设计**（怎么做到的）。
> 冲突以 Readme 为准。

---

## 一、三层

```
浏览器
  │
  ├─ GET /  /tools  /search?q=   ──▶  静态服务  :3000   server.js
  │                                    ├─ /assets/*        白名单托管（css / js）
  │                                    ├─ /tools/<项目名>/* 白名单托管（本地工具本体 ← tools/）
  │                                    └─ /api/config      → 告诉页面数据服务在哪
  │
  └─ GET {data.origin}/api/*     ──▶  数据服务  :3001   data-service/server.js
                                        └─ core（语义） → adapters（存储）
                                                            ├─ json-dir   catalog/*.json
                                                            ├─ json-file  单个 .json
                                                            ├─ js-file    单个 .js
                                                            └─ mysql      完整但未实测
```

### 「记录」与「本体」是两条路

一次点击会把这两条路都用上，但它们是分开的：

```
卡片显示     ← /api/tools        数据服务 → catalog/ 里的记录
点开卡片     ← /tools/ppt/       静态服务 → tools/ppt/ 里的项目文件
```

页面还会在**卡片渲染完之后**多发一个 `HEAD /tools/<项目名>/`，探一下本体在不在
（`assets/js/api.js` 的 `probeLocalProject()`），用来给卡片贴「本地副本未就位」角标。
它走的是**静态服务**那条路，不是数据服务。

这道探查要**提前**做，不能在点击时才做：点击必须同步开窗（见第三节），
中间插一次网络请求就会被浏览器当弹窗拦掉。所以顺序反过来 ——
渲染完就探好、记在卡片的 `data-tool-local` 上，点击时同步读出来。

它也只是**提前拦一道**，不是唯一防线：探的时候不在、探完又放进去的，网络正好抖了一下的，
都会漏过去 —— 那种情况由静态服务那张说明页兜底。两道都要在。

分开的理由和两个服务分开是同一个：**记录的存储方式会变**（文件 → MySQL），
**本体的存放位置也会变**（本地 → 别处）。把两者绑在一起，改一个就得动另一个。

两个服务**互不连接**：静态服务只是把数据服务的地址告诉浏览器，自己从不访问它。
所以数据服务搬到别的机器、换成 MySQL、中间加一层代理，静态服务和页面代码都不用动。

### 为什么是两个服务而不是一个

一个进程也能同时发页面和发数据，但那样「换数据库」就得动那个同时管着页面的进程。
分开之后，数据的替换被关在数据服务里 —— 这正是这次改造要买到的东西。

端口不写死：静态 `HOST`/`PORT`（默认 3000），数据 `DATA_HOST`/`DATA_PORT`（默认 3001），
两组都能用环境变量改，`npm start` 会自动把数据服务的地址传给静态服务。

## 二、语义住在哪（**这是本结构最重要的一条**）

归一化、`enabled` 过滤、关键词匹配规则、排序、热门补足、分页 —— **全部住在 `data-service/core/`**，
不住在适配器里。

适配器只回答一个问题：**「怎么把原始记录读出来」**。json 目录是「读目录下的 json」，
mysql 是「查表」。除此之外它们什么都不做。

```
core/normalize.js       归一化 / 校验 / URL 协议白名单 / 匹配 / 排序 / 分页 / 出站投影
core/memory-adapter.js  ★ 语义基准实现：拿一批记录，按契约提供 list / tags / hot
core/contract.js        常量（默认值、上限）
core/resolve.js         按 DATA_SOURCE 选适配器
core/log.js             日志去重
core/memory-source.js   「每次请求重新读一遍」的包装器
adapters/*.js           只管读盘 / 查询
```

**为什么这条这么要紧**：如果每个适配器各写一份匹配和排序，json 版和 mysql 版迟早会不一致 ——
而这种不一致极难发现，表现是「同一份数据换了个数据源，结果就不一样了」，
而且往往过很久才有人注意到。

三个文件类适配器（`json-dir` / `json-file` / `js-file`）都是「读出来 → 交给 memory 引擎」，
彼此只差读盘那一步，语义**不可能**分叉。

唯一允许分叉的是 `mysql.js`：它把过滤/排序/分页下推成 SQL（否则要把整表读进内存，
那就白用数据库了）。所以它必须拿 json 版**对拍** —— 对拍用例见 `adapters.md`。
`memory-adapter.js` 就是那个可执行的参照物。

## 三、前端为什么拆成这几个文件

```
index.html          结构 + 文案 + tailwind.config。**不含任何数据、任何业务逻辑**
assets/css/site.css 组件级样式 + 设计令牌（:root 变量）
assets/js/
  ui.js       展示层：esc / toast / 卡片模板 / 空状态 / 失败态 / 文案常量。不 import 业务模块
  pager.js    分批加载：按页取数 + 竞态令牌 + 空页保险 + 渲染下限
  api.js      唯一通道：数据服务地址解析 + fetch + 超时 + 错误归一化 + 本地副本探查
  views.js    三个视图各自的渲染。状态由参数传入，不读全局 state；渲染后探本地副本
  router.js   应用状态与路由：地址栏 ↔ 状态、视图切换、重试分发、点卡片分流
  main.js     唯一入口：绑事件 + 第一次渲染
```

依赖方向是单向的（`main → router → views → {ui, pager, api}`），
`views.js` 不 import `router.js`，所以不会绕成循环 import。

**改动的落点**：展示模板 → `ui.js`；分批加载 → `pager.js`；某个视图 → `views.js`；
地址栏/状态 → `router.js`；网络请求 → `api.js`；事件绑定 → `main.js`。

几个非做不可的细节，都在代码注释里写清了理由：

| 事情 | 不做的后果 |
|---|---|
| `src` 用绝对路径 `/assets/js/main.js` | 在 `/tools` 下会被解析成 `/tools/assets/...` → 404 |
| import 带扩展名 | 浏览器 ESM 不做扩展名补全 |
| `window.open()` 在同步栈里 | `await` 之后开窗会被当弹窗拦掉 |
| URL 协议白名单（只收 http/https，或站内单个 `/` 开头） | 数据离开代码后，`javascript:` 混进来就是 XSS |
| 卡片带 `data-tool-url` / `data-tool-name` / `data-tool-local` | 要么维护内存索引（白送的状态），要么点的时候查接口（来不及） |
| 本地副本探查放在**渲染后**而不是点击时 | 点击时探会让开窗落在 `await` 之后 → 被当弹窗拦掉 |
| 探查结果分 `missing` / `unknown` 两种 | 把「没探到」当成「没有」＝ 把不确定说成事实 |
| 竞态令牌 | 慢的旧响应落在新筛选结果后面 → 「筛了办公却冒出演示文稿的卡」 |
| 空页保险 | 服务端一旦给出「空页却说还有」，前端会无限打请求 |
| 每个出站请求都带超时（`fetchWithTimeout`） | 服务**卡住**时页面永远停在「正在加载工具……」，不报错也没有重试入口 |
| 超时与连不上分开标记（`err.timeout`） | 两句话合成一句，排障时就没有线索了 |
| 分类清单 `tagsLoaded` 门闩 | 数据服务一挂，深链 `?tag=办公` 会被静默清成「全部」 |

## 四、静态服务的白名单

`server.js` 只有**三张白名单**，其余地址一律 404：

1. **页面路由**（`ROUTES`）：`/`、`/tools`、`/search`。404 页的出口链接由这张表推导，
   所以以后加页面不用改 404 页，也不会出现「页面加了、404 页还写着本站只有几个页面」。
2. **前端资源**（`/assets/*`）：解析结果必须落在 `assets/` 内（防 `..` 与 `%2e%2e` 穿越），
   扩展名必须在 MIME 表里。
3. **本地工具本体**（`/tools/<项目名>/*`）：解析结果必须落在 `tools/` 内，
   扩展名必须在那张更宽的 `PROJECT_MIME` 表里。见下。

顺带的结果：`/catalog/*`、`/data-service/*`、`/docs/*`、`/Readme.md`、`/scripts/*`
因为都不在这三张表里，**天然全部 404** —— 记录数据、源码和文档永远不会被浏览器拿走。
这不是挨个加的规则，是白名单结构自带的性质。

### 两个服务都是只读的

静态服务只发文件、数据服务只发数据，**两边都没有写入接口**：除 `GET` / `HEAD`
（数据服务另有 `OPTIONS`）外一律 `405`，代码里没有收请求体、也没有写盘的分支。

所以记录（含 `likes`）只能由维护者在**本机**改文件。将来做点赞是一套单独设计的东西，
不是在这里放宽一条限制 —— 见 `Readme.md` 第八节「只读」。

### 第 3 张白名单：`/tools/<项目名>/`

它与前两张有三处不同：

1. **有目录的概念** —— 请求一个目录就找它的 `index.html`；**不出目录列表**。
2. **目录不带结尾斜杠时 302 补一个**再回来。少了这一步，项目页里 `style.css`
   这类相对引用会以 `/tools/ppt` 为基准解析成 `/tools/style.css`，表现是样式全丢，
   而且看不出跟这个跳转有关系。
3. **少了东西时给的是专门的提示页**，而不是笼统的 404：

   | 情形 | 响应 |
   |---|---|
   | `tools/<项目名>/` 不存在 | 404「这个工具还没有本地副本」（判据是**实时**看一眼目录，不是写死文案） |
   | 目录在、但请求的文件不在，或扩展名不在白名单 | 普通 404 |
   | 请求目录、目录里没有 `index.html` | 普通 404 |

`/tools` 与 `/tools/` 是**页面路由**，照旧 200；`/tools/<项目名>/` 才是托管。
两者共用前缀但**不冲突**：判据就是「前缀之后还有没有东西」——
一个是精确匹配，一个要求多一段。

> ⚠️ `tools/` 下的 HTML / JS **在本站源下执行，不是沙箱**。它能读到本站的公开接口、
> 能操作它自己那个标签页。只放信得过的项目 —— 见 `tools/README.md`。

缓存策略：`.html` / `.js` / `.css` 发 `no-cache`。本地工具，改完 JS 刷新还是旧文件
是真实会反复踩的坑；图片字体这类内容寻址的东西没必要回源。

## 五、端口与 CORS

| 服务 | 变量 | 默认 | 作用 |
|---|---|---|---|
| 静态 | `HOST` / `PORT` | `127.0.0.1` / `3000` | 页面与资源 |
| 静态 | `DATA_ORIGIN` | `http://127.0.0.1:3001` | **告诉浏览器**数据服务在哪（自己不连） |
| 数据 | `DATA_HOST` / `DATA_PORT` | `127.0.0.1` / `3001` | 数据接口 |
| 数据 | `CORS_ORIGIN` | 未设 → `*` | 逗号分隔的来源白名单 |
| 数据 | `DATA_SOURCE` | `json-dir` | 见 `adapters.md` |
| 数据 | `DATA_DIR` / `DATA_FILE` | `catalog` / — | 各适配器的数据位置 |

**默认 `*` 不算「写死」** —— 它不含任何主机名和端口，恰恰是「不写死」的表达。
本服务无 Cookie、无凭据、只发只读数据，规范上完全合法。
设了 `CORS_ORIGIN` 就改成回显白名单里的 `Origin` 并加 `Vary: Origin`，不在名单里就不发头。

### 连接层的三个上限（两个服务都设）

| 上限 | 值 | 管什么 |
|---|---|---|
| `headersTimeout` | 10s | 收完**请求头**的最长时间 |
| `requestTimeout` | 20s | 收完**整个请求**的最长时间 |
| `keepAliveTimeout` | 5s | 空闲长连接保持多久 |

Node 的默认值是按**公网长连接服务**定的（60s / 300s），对本站太宽：这里只有 GET / HEAD，
请求小到几十字节，本机实测个位数毫秒。放宽的代价是一个连上来却不发完请求的 socket
能白占着连接好几分钟 —— 表现是「服务在跑，但有的请求一直不回来」，这种错时有时无，最难查。

**它和前端那个 5 秒超时是两道独立的闸，缺一不可**：前端管「我不等了」（`AbortSignal` 掐断），
服务端管「你别占着我的连接」。只设前面那道的话，前端走了、连接还挂着。

### 「用哪边的数据」是一个找得到的开关

表里那两个默认值**在源码里各有一行**，用 ★ 标出来了：

| 想改什么 | 改哪里 |
|---|---|
| 用哪个适配器（清单文件 / MySQL / …） | `core/resolve.js` 的 `DEFAULT_SOURCE` |
| 清单文件放在哪 | `adapters/json-dir.js` 的 `DEFAULT_DIR` |

**搜 `★` 就能找到。** 环境变量优先级高于它们，所以跑临时组合不必动源码；
不设环境变量时用的就是这两行的值。代码里的默认值是**能直接跑的**，
所以「改成本地清单」和「改成数据库」都只是改一行的事，不用读别的代码去猜。

## 六、`npm start` 做了什么

`scripts/start.js` 起两个子进程，只多做一件加工：**把 `DATA_HOST`/`DATA_PORT`
推导成 `DATA_ORIGIN` 传给静态服务**。所以

```
DATA_PORT=4001 npm start
```

数据服务在 4001，页面拿到的 `data.origin` 也是 4001，前端一行不改。

行为：

- `stdio: 'inherit'` —— 两个服务的日志打在同一个终端里，不加前缀、不重定向
- **任一子进程退出，另一个也停掉**（页面没数据、或数据没人看，留着都没意义）
- 收到 `SIGINT` / `SIGTERM` 时先给子进程发信号，再等它们收尾，超时就直接退

单独启动的能力完整保留：`npm run start:static` / `npm run start:data`。

根目录的 `start.cmd` 是同一件事的「双击版」：它只做 `cd` 到自己所在目录 + `node scripts\start.js`，
**不重复任何配置**，端口的推导仍然只在 `scripts/start.js` 里发生一次。
它的用法是「**关掉那个窗口两个服务就一起停**」，靠的是上面那条 `stdio: 'inherit'` ——
子进程共用启动者的控制台，窗口一关系统会把挂在上面的进程全部收掉。
所以**不要给子进程加 `detached: true`**，加了就破坏了这个使用方式。

### Windows 上的一点实情

`Ctrl+C` 会把事件发给整个控制台进程组，两个子进程都收得到，正常退出。
而用 `taskkill /F` 硬杀父进程时，Windows 不保证级联 —— 本机实测两个子进程会一起消失、
端口全部释放，但这是操作系统行为，不是本脚本能保证的。真出现端口占着不放的情况：

```bash
netstat -ano | grep -E "127.0.0.1:(3000|3001).*LISTENING"   # 最后一列是 PID
taskkill //F //PID <那个 PID>
```

**别用 `taskkill /F /IM node.exe`** —— 那会杀掉机器上所有 node 进程，包括别人的。
