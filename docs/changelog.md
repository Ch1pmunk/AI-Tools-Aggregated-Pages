## 2026-09-28（续六）　首次推送被拒：远端 `README.md` 与本地 `Readme.md` 撞名

### 发生了什么

第一次 `git push` 被拒，理由是「远端上有你本地没有的内容」。
远端确实不是空的 —— 建仓库时勾了「Add a README file」，GitHub 自动生成了一份：

```
# AI-Tools-Aggregated-Pages
AI工具聚合页
```

**两行标题模板，没有实际内容。** 但它和本地那份 425 行的 `Readme.md` 在
**Windows / macOS 上是同一个文件名**（这两个系统不区分大小写），
而本机的 `core.ignorecase` 是 `true`，git 也跟着按不区分大小写来比对路径。

### 中间那次失败的尝试（记下来，别再踩）

先试了常规的 `git merge origin/main --allow-unrelated-histories`，
git 报「Automatic merge went well」—— **但它其实把两个名字当成两个不同文件**，
索引里同时出现 `README.md` 和 `Readme.md`。而磁盘上只能有一个，于是写 `README.md`
的时候**把本地那份文档覆盖成了 46 字节的模板**。`git status` 里的
` M Readme.md` 就是这个信号。

两份内容都没真丢（原文档完整存在 git 对象里），`git merge --abort` + `git checkout -- Readme.md`
就恢复了。**教训：`core.ignorecase=true` 的机器上，"自动合并成功"不等于"成功"。**

### 最后怎么解决的

用 **`-s ours` 策略**（注意：是 `-s ours` 策略，不是 `-X ours` 选项，两者不是一回事）：

```
git merge origin/main --allow-unrelated-histories -s ours -m "..."
```

`ours` 策略**不做逐文件合并**，直接拿本地的文件树当结果 —— 所以不存在同名文件打架。
远端那个提交作为祖先被完整保留（历史没被抹掉），只是它的改动（那份模板）不被接受。

结果：

```
*   d3eef2f  合并远端初始提交：文件树以本地为准，不接受自动生成的 README.md
|\
| * 5a07bd0  Initial commit          ← 远端提交，保留
* f04af30   初始提交：AI 工具聚合页
```

### 验证（阳性对照）

- `git diff f04af30 HEAD` → **输出为空**。这比"看着没问题"强：它证明合并后的文件树
  与本地原提交**逐字节一致**，41 个文件一个没多一个没少。
- `git ls-files | grep -i "^readme"` → 只有 `Readme.md` 一个。
- 磁盘上 `Readme.md` = 42167 字节 / 425 行，内容完整。

### 同步了 Readme 哪几节

- **§十三 「版本控制」**：新增一条硬规则 —— 根目录那份文档只能叫 `Readme.md`，
  不许再出现一个 `README.md`，并写明理由（大小写不敏感的系统上仓库会检不出来）。
  各子目录的 `README.md` 不受影响，它们各自目录下没有同名冲突。

## 2026-09-28（续五）　上版本控制：建本地仓库，推到 GitHub

### 改了什么

建了 git 仓库，写了 `.gitignore` 和 `.gitattributes`，推送目标
`github.com/Ch1pmunk/AI-Tools-Aggregated-Pages`（公开仓库）。

**仓库是"备份与分享"，不是"部署"。** 目标选的是「只把代码放上去」：
站点跑不跑在 GitHub Pages 上是另一件事，而且那件事**做不了** ——

> GitHub Pages 只发静态文件，不会跑 Node。而本站是**两个服务**，
> 数据全靠 `data-service/` 这个进程。传上去之后页面能打开，但会规规矩矩地显示
> 「未能读取工具数据 + 重试」—— 也就是说，**它正好会落进我们设计好的「数据不可用」态**。
> `/tools`、`/search` 这些路径同理，它们是 `server.js` 在路由，Pages 上不存在。
>
> 要真在 Pages 上跑起来，数据得从"服务端接口"变成"静态 JSON 文件"（发布时把 `catalog/`
> 导出成几个 `.json`，前端改成从文件读，分页筛选跟着挪到客户端）—— 那是一次独立改动，
> 而且会推翻现在「筛选和分页一律在服务端」那条明确禁令，必须重新论证一遍再做。

### 差点踩进去的坑：`core.autocrlf=true`

这台机器的 git 全局设了 `core.autocrlf=true`，意思是**检出时把文本文件的换行符统统换成 CRLF**。
而本项目的规矩是**除批处理外一律 LF**（`.editorconfig` 里刚定的），两者正好相反。
更麻烦的是，这个项目**真被换行符坑过一次**（`start.cmd` 那次，见「续二」）。

对策是 `.gitattributes`（**它的优先级高于 `core.autocrlf`**，写完那个全局设置就管不着这个仓库了）：

```
* text=auto eol=lf          # 默认一律 LF
*.cmd text eol=crlf         # 批处理无论如何都是 CRLF
```

这样「`start.cmd` clone 到任何机器上双击都能跑」是被**保证**的，不依赖谁的全局设置对不对。

**顺带记一条区分**：`.editorconfig` 和 `.gitattributes` 是**两件事，都要有** ——
前者管「编辑器保存时写成什么」，后者管「git 存进库、检出到磁盘时换成什么」。
编辑器写的文件不经过 git，git 检出的文件也不经过编辑器，**少一个就漏一头**。

### 另一件：提交身份

这台机器**没有配 git 提交身份**（`user.name` / `user.email` 都是空的），不配第一次提交直接失败。
配的是**仓库局部**（`git config --local`），没有动全局 —— 全局是别人的地盘，
而且这本来就是这个仓库自己的事。

用的是 `Ch1pmunk@users.noreply.github.com`（GitHub 的匿名邮箱形式），
**要换成别的随时改**：`git config --local user.email "你的邮箱"`。

### 同步了 Readme 哪几节

| 节 | 改了什么 |
|---|---|
| §十一 输出要求 | 目录树加 `.gitignore` / `.gitattributes` 两行 |
| §十三 项目管理与文档 | 新增「版本控制」小节：远端只是备份不是部署、换行符由 `.gitattributes` 保证、`.env` 那条要一直留着、临时脚本放系统 temp |

## 2026-09-28（续四）　自我审查：网络与项目管理的四处收口

对着「项目管理」和「网络管理」两条自查了一遍，**四处是量出来的问题，不是猜的**，
一并修掉；另有几条查完确认「有意不做」的，也写进文档免得下一轮再被当成漏掉的。

### 1. `/api/config` 一次加载发了两遍（**量出来的**）

页脚（`main.js` 的 `loadServerAddress`）和取数前的地址解析（`api.js` 的 `resolveDataOrigin`）
都要问「数据服务开在哪」，两处几乎同时发起；而请求带的是 `cache: 'no-store'`，
浏览器不会替我们合并。用一个桩件把 `fetch` 包起来数了一遍：

```
请求序列:  /api/config
          /api/config            ← 重复
          http://127.0.0.1:3001/api/tools?page=1&pageSize=12
```

**修法**：`fetchConfig` 加两层 —— **在途合并**（同时来的调用共用同一个 promise）+
**成功缓存**（地址一次会话内不会变）。**失败不留缓存**，否则「静态服务当时没起来、
后来起来了」时点重试会拿到缓存里的 null，重试按钮变成摆设。

改完复量：初始化 1 次、之后再问仍 1 次；服务没起来时返回 null 且**再问会真的重发**。

### 2. 两个服务都没设连接层上限 → 用 Node 默认的 60s / 300s

本站只有 GET / HEAD，请求小到几十字节。默认值是按公网长连接服务定的，一个不发完请求的
连接能白占 socket 好几分钟。现在设成 10s / 20s / 5s（`headersTimeout` / `requestTimeout` /
`keepAliveTimeout`）。这和前端那个 5 秒超时是**两道独立的闸**：前端管「我不等了」，
服务端管「你别占着我的连接」；只设前面那道，前端走了连接还挂着。

### 3. 加 `.editorconfig`：把 CRLF 那个坑从「散文」变成「机器守着」

`start.cmd` 必须是 CRLF 这条，之前只写在 Readme 和 changelog 里 —— 靠人记。
现在 `[*.{cmd,bat}] end_of_line = crlf` 由编辑器强制。整机 UTF-8 那条也一并写进去
（`charset = utf-8`），`*.md` 关掉自动删行尾空格（Markdown 里有时是有意义的）。

### 4. `package.json` 的 `type` 字段：**试了，然后撤回了**

本来想加 `"type": "commonjs"` 消掉 `MODULE_TYPELESS_PACKAGE_JSON` 警告。加上之后
**立刻试出问题**：Node 会把 `assets/js/*.js` 也按 CommonJS 解析（它们其实是浏览器的
ES module），于是「用 Node 直接 import 一个前端模块来验一段逻辑」这条路直接报语法错。

**这笔账不划算**：本项目零依赖、没有测试框架，用 Node 直接跑模块是唯一能自动验一段逻辑的
办法；拿它去换一句警告，是拿能力换整洁。撤回，并在 `package.json` 和 `assets/README.md`
里写明**为什么故意不写这个字段** —— 免得下次有人"顺手补上"。

### 5. 页面唯一一个「不走 `api.js` 的请求」补上了失败对策

`index.html` 里的 Tailwind CDN 是个一直被默认「不会挂」的地方。顺带查出一个**真 bug**：
后面那段 `<script>` 无条件执行 `tailwind.config = {...}`，CDN 一旦没下来就是
`ReferenceError: tailwind is not defined` —— 一条没用的报错，盖住控制台里真正有用的信息。

现在两句判断分开：CDN 没下来就**不写 config**，改为在页面顶部插一句能看懂的话。
那句话的样式**必须内联** —— 工具类这时一个都不存在，用 class 写的提示会和页面其余部分
一起变成白底黑字，等于没说。分支行为用 DOM 桩件两路都验过（加载成功 / 加载失败）。

顺带把 `tailwind.config = …` 改成 `window.tailwind.config = …`：浏览器里两者等价，
但上面刚用 `window.tailwind` 判断过、这里换个名字去写，读的人得先知道「它们其实是同一个
东西」才敢改；而且改成显式写法之后，这一行才**能在桩件里被验证**（就是它先把这个问题照出来的）。

**没有动技术基线**：Tailwind 仍然走 CDN，仍然零构建。要彻底不依赖外网就得把产物本地化，
那多一个构建步骤，和 Readme 定的基线冲突 —— 那是个更大的决定。

> **这个决定已经拍过了（2026-09-28）**：保持现状，不动构建基线。所以「样式押在境外 CDN 上」
> 是**明确接受**的取舍，不是漏项、也不是待办 —— 别再自动把它当成要修的东西。
> 但**「目前」是关键词**：这是当下的取舍，不是"以后不许动"。真要离线可用时，
> 路子在 `docs/principles.md` 第一条（把产物本地化，代价是多一个构建步骤）。
> 顺带记一条判断：这一处之所以**可以**接受，是因为它挂了只影响"好不好看"，
> 不影响数据和功能；如果哪天要往页面里加的是**功能性的**外部依赖（比如一个必须加载
> 才能用的库），那就不能照这条办 —— 那种挂了是真不能用。

### 6. 新增 `docs/principles.md`：把这一轮总结出来的判断规则收起来

这轮自查真正值钱的不是那几处修补，是**拿主意的规则**。所以单开一份文档收它们，
并且**刻意只收反复用得上、不写下来就会被忘掉的**（实现细节归代码注释，一次性决定归本文件）。

九条，每条都注明落在代码哪一处，否则就是口号：网络出口只有一处且例外必须登记、
超时是「掐断」不是「回来不采用」、两道闸、失败要分类、缓存必须能失败重来、
「有意不做」也要写下来、验证要带阳性对照、看似显然的加固可能是倒退、页面上只写
「渲染当刻成立」的话。

## 2026-09-28（续三）　卡片右下角画上点赞数

### 改了什么

`assets/js/ui.js` 的 `cardHtml`：卡片最后一行从「只有分类标签」变成
**标签靠左、点赞数靠右**（`items-end justify-between`），新增一个
`likesHtml(likes)` 负责画这个数。

**只动了展示层，一行数据代码都没碰**：`likes` 早就发给前端了
（`toPublic()` 的白名单里一直有它，`/api/hot` 和 `/api/tools` 都带），
所以这是纯画法改动，接口、契约、适配器全不动。

### 三条约束（都不是随手定的）

**1. 它是读数，不是按钮。** 没有边框、没有底色、不跟着卡片 hover 变色。
本站没有任何能改 `likes` 的入口（上一轮定的只读，见下面那条），画成能点的样子
是最坏的结果 —— 用户点一下没反应，只会认为页面坏了，而不是认为「这里本来就不能点」。
同理，卡片 hover 表达的是「能打开」（那是右上角箭头的意思），点赞数和那个动作无关，
所以不跟着一起变。

**2. 0 照实画出来，不画空白。** 空白和「不知道有多少赞」长得一模一样，
而这两件事必须能分开 —— 这是这个项目反复强调的那条（第十二节）。
另外，画 0 **不违反**「不知道 ≠ 没有」：`likes` 缺省就是 0，这是记录契约里写明的默认值
（`core/normalize.js` 的 `toLikes`），所以这个 0 是「确定一个赞都没有」，
不是替谁下结论；真正取不到数据时根本不画卡片，也就没有这个数。

**3. 三个视图共用同一个模板。** 首页热门、工具页、搜索页用的是同一个 `cardHtml`，
所以点赞数在三处都出现，不是只加在首页 —— 首页那 6 张卡本来就按 `likes` 排序，
数字画出来，排序依据对访客就是看得见的，不是黑箱。

| 语法 | `node --input-type=module --check -` 通过 |

| 端到端 | 起两个服务：`/api/hot` 仍带 `likes:0`；`/assets/js/ui.js` HTTP 200 且 `text/javascript; charset=utf-8`，取回来的内容里确实带着新那段 |
| 清理 | 只按 `netstat` 找到的 PID 停进程（**没有用 `taskkill /F /IM node.exe`**）；停完两个端口都空、没有本项目进程残留 |

## 2026-09-28（续二）　根目录加 `start.cmd`：双击启动，关窗即停

### 改了什么

根目录多一个 **`start.cmd`**，双击就能起两个服务，**关掉那个窗口 = 两个端口都停**。

**它是一层壳，不是第二个启动器。** 整个文件只做三件事：`cd` 到自己所在目录、
`node scripts\start.js`、失败时 `pause` 一下好让人看清报错。**端口仍然只在
`scripts/start.js` 里推导一次** —— 这是这个项目「端口只在一处配」那条规矩的延续，
多一个入口不能多一份配置。

`scripts/start.js` 只加了一行输出（「关掉这个窗口、或按 Ctrl+C，两个服务会一起停」）。

### 「关窗即停」是谁保证的

不是脚本保证的，是 Windows：`scripts/start.js` 用 `stdio: 'inherit'` 起子进程，
两个服务因此**共用启动者的控制台**；控制台窗口一关，系统会把挂在这个控制台上的进程全部收掉。

**所以有一条禁令现在更要紧了：不要给子进程加 `detached: true`。** 加了就变成
「关了窗口进程还在」，而这个文件存在的全部意义就是「关窗即停」。这条写进了
`scripts/README.md` 的行为表和 `docs/architecture.md` 第六节。

### 踩到的坑：LF 换行让 cmd.exe 的解析器丢失同步

第一版 `start.cmd` 写成了 **LF 换行**，跑起来的症状是：

```
The system cannot find the file specified.
'…动」的壳，不重复任何配置' is not recognized as an internal or external command,
```

——注释行被**从中间截断**，后半截当成命令去执行了。原因是 cmd.exe 读批处理是
按块读、按 `CRLF` 认行，**LF 换行 + 多字节字符**会让它丢同步。改成 `CRLF` 后立刻正常。

**这个症状极具误导性**：报错指向的文件名、乱码片段都跟真正的原因没关系，看起来像编码问题，
其实是换行符格式问题。所以两件事分开：

| | 结论 |
|---|---|
| 字符集 | 这台机器整机统一 UTF-8，脚本里直接写中文，不要为「某些终端可能乱码」做任何妥协 |
| 换行符 | **批处理文件必须是 `CRLF`**，这是文件格式问题，跟字符集无关 |

改 `start.cmd` 时**换行符要保持 `CRLF`**（用能选换行符的编辑器改，或者改完把 LF 转回 CRLF），
Readme 第十三节的运维备忘里记了这条。

### 验证

| 验的是什么 | 结果 |
|---|---|
| `start.cmd` 能起来 | 双击路径（`cmd /c start.cmd`）下两个服务都起、两个端口都听 |
| 进程树 | `cmd.exe → node scripts\start.js → {static, data}`，**没有 `detached`** |
| 级联 | 杀掉静态服务一个进程，`start.js` 自己把数据服务停掉、自己也退出，端口全空 |
| 关窗 | ✅ **实测通过**（人工操作：双击 `start.cmd` 打开，点 X 关闭；关闭后两个端口都空、node 进程 0 个、没有残留的启动窗口）。这一条在开发环境里复现不出来 —— 那里没有交互式窗口站，`Start-Process` 起的 cmd 拿不到主窗口，`CloseMainWindow()` 返回 `False`，走不到「真关一个窗口」那条路 —— 所以当时只核实了它的两个前提（子进程共用控制台、没有 `detached`），最后靠人工确认收口。**「开发环境复现不出来」不等于「行为不可靠」，这两件事别混。** |

### 同步了 Readme 哪几节

| 节 | 改了什么 |
|---|---|
| §十 服务器与访问配置 | 启动方式里补「不想开终端就双击根目录 `start.cmd`」一条，写明关窗即停 |
| §十一 输出要求 | 目录树加 `start.cmd` 一行 |
| §十三 运维备忘 | 补「启动 = 双击 `start.cmd`，关窗即停」；补一条「改 `start.cmd` 必须保持 CRLF」 |

## 2026-09-28（续）　只读约束；本地副本探查；超时异常；★ 数据源开关

这一轮四条，前三条都是**「出错时怎么办」**，第四条是**「数据从哪来」的开关**。

### 1. 只读：不给访客任何改数据的能力（硬性）

点赞的写入路径**不做**，而且不是「还没来得及做」—— 是**有意不开放**。

- 两个服务除 `GET` / `HEAD`（数据服务另有 `OPTIONS`）外一律 `405`，不看路径、不看请求体。
- `likes` 因此是**记录里的静态值**：读得到、算得出热门，但改它只能改文件。
- 将来做点赞是**新做一套东西**（谁能改、怎么防刷、要不要校验来源），
  在那套设计定下来之前**不放宽任何一条**。理由很简单：一个「先开着以后再说」的写接口
  就是永久的口子 —— 它一旦存在，防刷和鉴权就得在它后面补，而不是在它前面决定。

**怎么确认它真的只读**（跑过的，不是声称）：

```
POST/PUT/PATCH/DELETE  →  :3000 全部 405，:3001 全部 405（含 /api/tools/ppt 这种具体记录路径）
POST /api/tools        →  405 {"error":{"code":"METHOD_NOT_ALLOWED","message":"只支持 GET / HEAD"}}
grep writeFile|createWriteStream|appendFile|mkdir|unlink|req.on('data'
                       →  整个服务端 0 命中
```

**没有写接口不是靠约定，是代码里无处可写** —— 没有收请求体的分支，没有一处写盘。
这条比「记得别加写接口」可靠得多。

### 2. 本地副本探查：点击之前就知道「货在不在」

以前点了卡片就开窗，本体不在时用户看到的是一个新窗口里的说明页，还得自己关掉。现在提前拦一道：

```
卡片渲染完 → views.js 的 probeLocalCards() 挨个 HEAD 一下站内地址的卡片
           → api.js 的 probeLocalProject() 给出 true / false / null
           → router.js 的 openTool() 在点击时按结果分流
```

- **结果分三种，`null` 最要紧**：`true` 在 / `false` 明确 404 不在 / `null` 超时、5xx、网络错。
  `null` **什么都不标**，点击照旧打开。把「没探到」说成「没有」，就是把不确定说成事实 ——
  和「0 条 vs 不知道有几条」是同一条道理，所以这里也做了三态。
- 明确不在的卡片贴一个角标「**本地副本未就位**」，点了只给轻提示，不开一个注定是错误页的新窗口。
- **探查必须在渲染后做，不能在点击时做**：点击必须同步开窗，中间插一次网络请求
  就会被浏览器当弹窗拦掉。所以结果写在卡片的 `data-tool-local` 上，点击时同步读。
- 它**必然会漏**（探完才放进去的、网络正抖的），所以静态服务那张说明页是**兜底，留着**。
  两道防线各管一段：探查管体验，说明页管正确。

### 3. 超时：服务卡住时页面不能永远停在加载中

- `api.js` 顶部两个上限：取数 **5000ms**（`REQUEST_TIMEOUT_MS`），
  本地副本探查 **2500ms**（`PROBE_TIMEOUT_MS`，它只是加个角标，不值得挂 5 秒）。
- **所有出站请求都必须走 `fetchWithTimeout()`**，一个都不能漏。
- 超时一到 `AbortSignal` 中止请求 → **对面后来才回的响应根本到不了页面**，
  这才是「丢掉超时的返回」的落地方式（不是靠调用方记得判断）。
  这挡的是「迟到的响应」；另有一道竞态令牌挡「成功但已经过期」的响应 —— 两道挡的不是同一件事。
- 超时和「连不上」**分开标记**（`err.timeout`）并分开给文案：连不上是「服务没起来」，
  超时是「服务起来了但不应答」，要查的东西不一样。状态行说清之外，超时**额外弹一条轻提示**
  （状态行那行小字说不清是哪一种）。
- 新增文案常量 `TIMEOUT_TEXT = '读取工具数据超时。'`，与原有的 `FAILURE_TEXT` 并列。

**顺带抓到一个真 bug**：`fetchConfig()` 以前**没有超时**。它是解析数据服务地址的第一步，
静态服务一旦卡住（不是关掉，是卡住），`resolveDataOrigin()` 就永远不返回 ——
页面停在「正在加载工具……」，既不报错也不长重试按钮。已改为走 `fetchWithTimeout()`。

### 4. ★ 数据源开关：一行代码选「用哪边的数据」

「用清单文件」和「以后用数据库」之间要能一眼切换，不能靠读代码去猜默认值在哪：

| 想改什么 | 改哪里 |
|---|---|
| 用哪个适配器 | `data-service/core/resolve.js` 的 `DEFAULT_SOURCE` |
| 清单文件放在哪 | `data-service/adapters/json-dir.js` 的 `DEFAULT_DIR` |

两行都用 ★ 标出来了，**搜 `★` 就能找到**。环境变量（`DATA_SOURCE` / `DATA_DIR`）优先级更高，
所以跑临时组合不必动源码。当前默认值是 `json-dir` + `catalog`，也就是**直接能跑的那一个**。

### 验证

前端行为用了一个临时 DOM 桩脚手架驱动**真实模块**打**真实服务**（跑完已删），22 项全过：

| 组 | 验的是什么 |
|---|---|
| 探查 | 404 → `false`；200 → `true`；外链 / 空 url → `null`；超时 → `null`（实测 2505ms 返回，不是 2500 时就被当 false） |
| 卡片标注 | `missing` 的卡片状态位被换成角标；外链与空 url 标 `na`；重复调用幂等 |
| 点击分流 | `missing` → 不开窗 + 提示「还没有本地副本」；`unknown` → 照旧开窗；空 url → 「即将上线」 |
| 超时 | 取数实测 5006ms 抛错且 `isTimeout` 为真；状态行与首页失败态都说「超时」而不是「连不上」 |

## 2026-09-28　热门改用点赞数；工具本体可在网页端打开；补齐多级文档

### 改了什么

**1. 首页热门：`hot` 布尔 → `likes` 点赞数**

原来的热门标记是布尔值（`hot: true`），只能表达「是/不是热门」。现在换成数字 `likes`
（非负整数，缺省 0），首页按 **`likes` 降序 → `order` 升序 → `id` 升序** 取前 6 个。

- 换的理由：布尔没有程度之分，排不出先后，而首页那 6 张卡今天和明天必须是同一批。
  数字还**能被累加** —— 它将来直接对应数据库里的一列（`schema.sql` 里已经是 `likes INT`）。
- **次级键不能省**：点赞数会大量并列（尤其清一色的 0），只按 `likes` 排的话，
  同一批数据两次请求可能给出不同的 6 个。`compareHot()` 是新的排序函数，
  `mysql.js` 的 `ORDER BY t.likes DESC, t.sort_order ASC, t.id ASC` 是同一件事的 SQL 说法。
- 归一化：负数、`NaN`、非数字一律归 0，小数取整（`toLikes()`）。
  排序键里混进 `NaN` 会让整个 `sort` 的顺序变成未定义行为。
- `likes` **发给前端**（`toPublic()` 白名单里），
  但**没有写入路径** —— 没有「点一下 +1」的入口，也没有存的地方，见下面「有意没做」。

**2. 本地工具本体：点击卡片 → 网页端打开**

`tools/<项目名>/` 下的项目本体现在由静态服务托管（`server.js` 的 `sendProject`），
地址是 `/tools/<项目名>/`。卡片的 `url` 填这个地址，点开就是本地那份。

- 为此 `safeUrl()` 放行**站内单个 `/` 开头的相对地址**（以前一律拒掉）。
  同时挡掉 `//evil.com` 这种协议相对地址 —— 那是外站。
- `/tools/<项目名>/` 是**第三张白名单**（`PROJECT_MIME`），比 `/assets` 那张宽
  （多了 `.mjs` `.map` `.txt` `.woff` `.ttf` `.gif` `.webp` `.wasm` 等）：
  这里放的是别人项目的成品，收得太紧会「文件明明在却打不开」，而且错得很安静。
- 请求目录给它的 `index.html`，**不出目录列表**；
  **目录不带结尾斜杠时 302 补一个**，否则项目页里 `style.css` 这类相对引用会指到上一级。
- 顺带加了 `X-Content-Type-Options: nosniff`。

**3. `/tools` 没有对应项目文件夹 → 专门的异常反馈**

以前是笼统的「这里没有页面」。现在是单独一页：**「这个工具还没有本地副本」** ——
地址是对的，只是货还没到。判据是**实时**去看一眼 `tools/` 下有没有那个目录，不是写死的文案。

区分三件事：

| 情形 | 响应 |
|---|---|
| `tools/<项目名>/` 不存在 | 404「这个工具还没有本地副本」 |
| 项目在、文件不在，或扩展名不在白名单 | 普通 404 |
| 项目在、目录里没有 `index.html` | 普通 404 |

**4. 补齐多级文档**

每个目录下各加一份 `README.md`（`assets/`、`catalog/`、`tools/`、`data-service/`、
`scripts/`、`docs/`），讲「这个目录是干什么的、和谁配合」。`docs/` 下四份继续管跨目录的设计决定。

### 修掉的一个 bug（自己写出来的，测试时抓到）

`sendProject` 第一版把「补斜杠」写在了判断目录之前，于是**任何**不以 `/` 结尾的路径都会 302 ——

## 2026-09-28　数据与页面分离（三层结构）

### 改了什么

把「工具数据」从 `index.html` 里搬出去，分成三层：静态页 → 数据服务 → 数据源适配器。

**数据**
- `index.html` 里那份硬编码的 `const TOOLS` 删除。工具记录改住 `catalog/*.json`，一个文件一条。
- 新增 `data-service/`：独立进程、独立端口。`core/` 放语义（归一化 / 过滤 / 匹配 / 排序 / 分页 / 出站投影），`adapters/` 只负责「怎么把原始记录读出来」。
- 四个适配器：`json-dir`（默认）、`json-file`、`js-file`、`mysql`。**`mysql.js` 完整实现但未实测**（本机没有 MySQL 实例），接入前必须走 `docs/adapters.md` 的验证清单，与 json 版对拍。
- `catalog/_template.json` 是模板；`_` 与 `.` 开头的文件被跳过。
- 新增 `toPublic()` 出站投影：`enabled` 等内部字段**不再发给前端**。原实现把 `enabled` 一起发了出去，与契约「由服务端过滤」不符。
- 记录新增 `order` 字段（越小越前，缺省 1000）。排序固定为 `order asc, id asc` —— `readdir()` 的顺序由文件系统决定，没有确定的排序键，分页会重复和漏项。
- `url` 加协议白名单：只收 http/https，其余（如 `javascript:`）归一化成空串。

**前端**
- 单文件拆成 `index.html` + `assets/css/site.css` + `assets/js/{ui,pager,api,views,router,main}.js`。ES module，**仍然零构建**。
- 工具页与搜索页改为**按页向服务端取数**（`PAGE_SIZE = 12`），不再一次拉全量。
- `LOAD_DELAY_MS` → `MIN_VISIBLE_MS`，语义明确为**渲染下限而不是请求延迟**：请求立即发出，只是「出结果」被压后。
- 状态行从 2 句扩成 4 句 + 1 空态（首次加载 / 加载更多 / 全部加载完 / 成功但 0 条留空 / 失败 + 重试）。
- 新增竞态令牌、空页保险、`tagsLoaded` 门闩。
- 删除客户端的 `filterTools` / `allTags` —— 分页之下本地过滤只能过滤「已加载的那一页」，计数必然错。
- 全站删掉移动端适配：35 个响应式类名分布在 22 行，全部收敛成桌面一套。`viewport` meta **保留**（那是另一个决定）。

**静态服务**
- 新增 `/assets/*` 白名单托管（穿越防护 + MIME 白名单 + 缓存策略）。它与页面 `ROUTES` 是**两张独立的表**。
- `/api/config` 新增 `data.origin`，页面据此定位数据服务。
- `.html` / `.js` / `.css` 发 `no-cache`。

**启动**
- 新增 `scripts/start.js` + `npm start`：一条命令起两个服务，由 `DATA_HOST`/`DATA_PORT` 推导出 `DATA_ORIGIN` 传给静态服务 —— **改一处端口，两边一起跟上**。单独启动的能力保留（`npm run start:static` / `npm run start:data`）。
- 新增根目录 `tools/`（**空**）：预留给将来解压后的开源项目本体。**本版不写任何扫描 / 托管 / 部署代码**，方案未定。
