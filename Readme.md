本项目为中文 AI 工具导航网站。以下规范是它的唯一需求依据；**任何代码改动都要同步更新本文档**。设计细节（怎么做到的）在 `docs/`，两者冲突时以本文档为准。
视觉参考「简序」那种极简、瑞士国际主义、编辑排版风格，但不照抄品牌和文案。不要使用 React / Vue；不要反问，按最佳判断补全。

## 一、网站定位

一个专门收集 AI 工具的导航站，帮助用户快速找到并实际使用 AI 工具。共三个页面：**首页**、**AI 工具页**、**搜索结果页**。

收录口径：**只收录开源项目**。这是长期成立的一句话，在首页 Hero 里明写出来（见第四节）。

## 二、整体风格

- 主题色：米白色。背景 #F7F4EE / #FAF8F3；顶部栏 #EFE9DD（比主体略深，用来区分）；卡片 #FFFFFF；主文字 #111111；次要文字 #6B7280；边框 #E8E3DA。
- 极简、克制、专业、瑞士国际主义、编辑排版。
- 大量留白，细边框，大圆角，轻阴影，低饱和标签。
- 字体：Inter（拉丁）+ 思源黑体 / Noto Sans SC，回落到系统无衬线。标题大而粗，层级清晰。
- **只做桌面端**。不写任何响应式断点（`sm:` / `md:` / `lg:` / `xl:` 一律不用），不写移动端样式。窗口变窄时不要求塌成单列 —— 这件事等以后有明确计划再说。
- 禁止：花哨渐变、重阴影、玻璃拟态、3D 图标、AI 味插画、过多装饰。
- 技术基线：**多文件 ES module + Tailwind CDN + 原生 JS，仍然不做任何构建**（无打包、无转译、无 npm 运行依赖）。不引其他 CSS 框架。
  - `index.html` 只放结构、文案和 `tailwind.config`；样式在 `assets/css/site.css`，逻辑在 `assets/js/*.js`。
  - ES module 的 `src` 必须写**绝对路径**（`/assets/js/main.js`）：写相对路径时，`/tools` 下会被解析成 `/tools/assets/...` 而 404。模块之间的 `import` 走相对模块自身的地址，带 `.js` 扩展名。
  - 色板**在两处各写一份，改一处必须同时改另一处**：`index.html` 的 `tailwind.config`（Play CDN 运行时读它生成工具类）和 `site.css` 顶部的 `:root` 变量（手写 CSS 读它）。Play CDN 读不到 CSS 变量，反过来手写 CSS 也不该散落魔法色值，所以两遍是必须的。

## 三、页面与路由

路径与页面一一对应，严格白名单，**除下表外的一切地址一律 404**（如 `/abc`、`/index.html`、`/favicon.ico`）。

| 地址 | 内容 |
| --- | --- |
| `/` | 首页（根路径直接导向首页） |
| `/tools`、`/tools?tag=办公` | AI 工具页 |
| `/search?q=关键词`、`/search?q=关键词&tag=办公` | 搜索结果页 |
| `/search`（无 q，或 q 为空 / 纯空格） | **302 → `/tools`** |
| `/assets/*` | 前端资源（css / js）。另一张白名单，见下 |
| `/tools/<项目名>/` | 本地工具本体。又一张白名单，指向 `tools/<项目名>/` 下的文件（见第八节） |
| `/api/config` | 服务配置接口（见第十节） |
| 其他 | 404 页面 |

- 结尾斜杠等价：`/tools/` 与 `/tools` 同页。
- 搜索参数用 `q`，分类参数用 `tag`；两者都进地址栏，刷新 / 前进后退 / 分享都能还原。
- 前端用 History API 做站内跳转（不刷新页面）；路径与查询串是状态的唯一真相来源（唯一例外是列表滚出了多少页，见第五节）。
- 404 页面沿用同一套米白视觉，回显被访问的路径（需转义）。出口链接由 `server.js` 的 `ROUTES` 推导，**不写死页面数量**，也不出现「本站只有几个页面」这类说法（见第十二节）。

### 静态资源白名单

`/assets/*` 是**另一张**独立白名单，与页面路由表分开（页面路由表只登记页面，否则 404 页的出口会多出不是页面的东西）。两条规则：

1. 解析结果必须落在 `assets/` 目录内，**否则一律 404** —— 防 `..` 与 `%2e%2e` 穿越。
2. 扩展名必须在 MIME 白名单里（`.html` `.js` `.css` `.json` `.svg` `.png` `.jpg` `.jpeg` `.ico` `.woff2`），不在就不托管。

因此 **`/catalog/`、`/data-service/`、`/docs/`、`/Readme.md`、`/scripts/` 永远不对外托管**，一律 404。这不是挨个加的黑名单规则，是白名单结构自带的性质 —— 记录数据、服务端源码、设计文档都不会被浏览器拿走。

### 本地工具白名单（`/tools/<项目名>/`）

第三张白名单，指向 `tools/<项目名>/`。规则：

1. 第一段就是项目名，解析结果必须落在 `tools/` 之内，**否则一律 404** —— 同样防穿越。
2. 请求目录时代之以它的 `index.html`；**不出目录列表**。
3. 扩展名必须在 `PROJECT_MIME` 白名单里 —— 这张表比 `/assets` 那张宽（多了 `.mjs` `.map` `.txt` `.woff` `.ttf` `.gif` `.webp` `.wasm` 等），因为这里放的是别人项目的成品，收得太紧会「文件明明在却打不开」，且错得很安静。
4. **目录不带结尾斜杠时 302 补一个斜杠**再回来。少了这一步，项目页里 `style.css` 这类相对引用会指到上一级去，表现是样式全丢。
5. **项目文件夹不在时，给的是专门的提示页**（「这个工具还没有本地副本」），不是笼统的「这里没有页面」—— 地址是对的，只是货还没到。判据是实时去看一眼目录在不在，不是写死的文案。

`/tools`（无斜杠）与 `/tools/` 是**页面路由**，照旧 200；`/tools/<项目名>/` 才是托管。
两者共用前缀但不冲突：一个是精确匹配，一个要多一段。

> ⚠️ `tools/` 下的 HTML / JS **在本站源下执行，不是沙箱**。只放信得过的项目，详见 `tools/README.md`。

缓存：`.html` / `.js` / `.css` 发 `no-cache`（本地工具，改完刷新还拿到旧文件是真实会反复踩的坑），图片字体这类发 `max-age=3600`。`/tools/<项目名>/` 下的一切都发 `no-cache` —— 那是维护者自己刚放进去、还在改的东西；另外统一带 `X-Content-Type-Options: nosniff`，不让浏览器自己猜类型。

顶部栏：左侧居左放两个导航选项「首页」「AI工具页」，右侧放一个搜索框。顶栏底色比主体略深（#EFE9DD），底部再加一条 1px 黑色描线（#111111）与内容区分隔。
导航是真链接（支持中键 / Ctrl+点击新标签打开），当前项黑底白字选中。搜索结果页属于工具列表的过滤视图，此时高亮「AI工具页」。

## 四、首页视图

1. **Hero / 文字介绍区**：小标签「AI Tools Directory」+ 超大标题 + 一段简短介绍 + **一行收录口径**「只收录开源项目」，排版自拟。文案方向：本站专门收集 AI 工具，提供方便快捷的导向和实际使用入口。大标题、少装饰、左对齐、大量留白。
   - 收录口径那行是 Hero 的收尾：短黑描线 + 主文字色的一行小字（比介绍段更重，但比大标题轻得多），不要做成按钮或色块。
2. **热门工具推荐区**：小标签「Hot」+ 标题「热门工具推荐」+ 计数。网格横 3 列 × 竖 2 行，最多 6 个卡片位。
   - 数据来源：`GET /api/hot?limit=6`（见第八节）。取哪几个由服务端定：**按点赞数 `likes` 降序**，同点赞数按 `order`、`id` 升序，取前 6 个。服务端不凑数。
   - 点赞数是记录里的一个**真字段**（`likes`，非负整数，缺省 0），不是临时的排序技巧 —— 它将来直接对应数据库里的一列，所以现在就当正式字段对待。之所以不用「是否热门」这种布尔标记：布尔只能表达「是/不是」，没有程度之分，也就排不出先后，而首页那 6 张卡今天和明天必须是同一批。
   - 这个数**同时画在卡片右下角**（见第五节）—— 排序依据对访客是看得见的，不是黑箱：卡片为什么排在这儿，看那个数字就知道。
   - 拿到的不足 6 个时，剩下的槽位渲染虚线占位卡（撑出网格结构）。**成功拿到数据、但一条都没有**时显示空状态「暂无工具收录」。
   - **拿不到数据时（数据服务不可用），一个卡片都不画 —— 包括虚线占位卡**，改为显示失败文案 + 重试。占位卡不只是装饰，它等于宣称「本站的工具不足 6 个」，那是编造事实。
   - 计数只在成功拿到数据之后才出现。拿不到数据时它是空的，**不是「共 0 个」**。
3. 其余地方暂时不放内容。

## 五、AI 工具页视图（`/tools`）

- 列出所有已收录工具，**只按分类过滤**（搜索不在这里，已独立成页）。过滤与分页**全部由数据服务做**，前端不做本地过滤。
- 页头：小标签「All Tools」+ 标题「AI 工具页」+ 计数 + 一句简短说明。
  - 无分类筛选时显示「共 m 个工具」；有筛选时显示「筛选出 n / m 个工具」（按是否真的在筛选判断，而非按数量是否相等，否则筛完恰好全中会看不出过滤生效）。
  - n 与 m 都来自服务端（`total` / `totalAll`）。**不许用「已经加载出来的卡片数」当计数** —— 分页之下那只是已加载的部分。
- 分类标签筛选条：分类由数据服务派生（`GET /api/tags`），不硬编码。胶囊样式，选中黑底白字，未选中白底灰边；选中的分类写进地址栏 `?tag=`。
  - 分类还没取到、或一件工具都没有时，**整条不渲染** —— 连「分类」标签和「全部」胶囊也不出，它们的内容同样是数据派生的。
- 网格布局：桌面 3 列。
- **卡片分批加载**（工具多起来之后，不能一次全塞进 DOM，也不能一次全拉走）：
  - **按页向服务端取**：一次取 `PAGE_SIZE = 12` 页大小的一页，滚到列表底部、状态行进到视口附近时再取下一页，直到取完。
  - 卡片下方留一行淡小字（居中、13px、次要文字色 `#6B7280`），说明当前状态，**下表六行，其中一行是留空**：
    | 情形 | 文案 |
    | --- | --- |
    | 首次加载中 | 正在加载工具…… |
    | 还有下一页 / 正在取下一页 | 正在加载更多工具中…… |
    | 全部取完 | 已加载全部工具 |
    | 成功但一条都没有 | 留空（由空状态块说明） |
    | 请求失败（连不上） | 未能读取工具数据。+ 重试按钮 |
    | 请求失败（超时） | 读取工具数据超时。+ 重试按钮，**另弹一条轻提示** |
  - 这几种都是**渲染当刻成立的状态**（见第十二节），不声称任何规模或进度。
  - **超时和连不上要分开说**：连不上是「服务没起来」，超时是「服务起来了但不应答（卡住了）」，要查的东西不一样。状态行上那句字说明不了它是哪一种，所以超时**额外弹一条轻提示**直接告诉用户。两种情形的错误对象都带着超时标记，页面据此挑文案。
  - 这一行同时承担本页的底部留白，所以 0 条结果时把它**留空**而不是隐藏（隐藏会让页面贴底）。
  - `hasMore` **只认服务端返回的那个字段**，前端不许用 `items.length < pageSize` 推导。
  - 三个可调参数写在 `assets/js/pager.js` 顶部，注释里都写了理由：
    - `PAGE_SIZE = 12`：每页张数（桌面 3 列 × 4 行）。
    - `PRELOAD_PX = 0`：触底提前量。**保持 0** —— 提前取的话，状态行会在进入视口前就被新卡片顶走，那行字写了等于没写。
    - `MIN_VISIBLE_MS = 350`：一页渲染的**最短展示时间**。它是**渲染下限，不是请求延迟** —— 请求一发出就走，只是「出结果」被压后到至少这么久。不设下限的话加载态只闪一帧，等于没写；设 0 = 最快，但看不到加载态。
  - **页数不进地址栏**：它是滚动进度，不是可分享的状态，刷新回到第一页。只有地址栏里的 `q` / `tag` 变了才重置。
  - 筛选条件变化时必须能丢弃在途的旧请求的结果（否则慢的旧响应会落在新结果后面，出现「筛了办公却冒出演示文稿的卡」）；服务端若给出「空页却说还有」，客户端必须就此收手，否则会无限打请求。
- 筛不出任何工具时显示空状态块（点「全部」查看所有工具）。
- 卡片内容：图标、工具名称、简短描述、分类标签、点赞数、状态（`url` 为空显示「即将上线」，有值显示箭头；指向本地工具但本体不在时显示「本地副本未就位」）。
- **点赞数画在卡片右下角**，与分类标签同处卡片最后一行：标签靠左（可换行），点赞数靠右、与标签行底部对齐。
  - **它是读数，不是按钮** —— 没有边框、没有底色、不随卡片 hover 变化。本站没有任何能改 `likes` 的入口（见第八节「只读」），画成能点的样子、点了却没反应，会被当成页面坏了；卡片 hover 表达的是「能打开」，那是右上角箭头的意思，和点赞数无关。
  - **0 要照实画出来**，不许画成空白：空白与「不知道有多少赞」长得一模一样，而这两件事必须能分开（同第十二节）。它与「未能读取工具数据」更是两回事，不许互相顶替。
  - 画 0 **不违反**第十二节那条「不知道 ≠ 没有」：`likes` 缺省就是 0，这是记录契约里写明的默认值（`core/normalize.js` 的 `toLikes`），所以这里的 0 是「确定一个赞都没有」，不是替谁下结论。真正取不到数据时根本不画卡片，也就没有这个数（见第九节）。
  - 三个视图（首页热门、工具页、搜索页）**共用同一个卡片模板**，所以点赞数在三处都出现，不是只加在首页。
- **「本地副本未就位」这个角标**：卡片渲染完之后，页面挨个向服务端探一次本地工具的本体在不在（`url` 是站内地址的才探），确认不在就给这张卡贴上角标。探的结果记在卡片的 `data-*` 上，点击时同步读出来。
  - 为什么探在渲染后、不在点击时：点击必须同步开窗（见第九节），中间插一次网络请求就会被浏览器当弹窗拦掉。
  - **探不到 ≠ 没有**：只有明确收到 404 才算「不在」；超时、5xx、连不上都算「不知道」，这时**什么都不标**，点击照旧打开，由服务端给出说明页。把「没探到」说成「没有」，就是在把不确定说成事实（同第十二节「0 条 vs 不知道有几条」一条道理）。
  - 这个角标说的是**探查当刻的事实**（刚探过，确实没有），不是会过期的规模描述，所以不违反第十二节。
- 新增工具只改 `catalog/` 下的数据文件，不改任何渲染逻辑（见第八节）。

## 六、搜索结果页视图（`/search?q=`）

- 主体与 AI 工具页相同（页头 + 分类胶囊 + 卡片网格），页头标题行右侧额外多一行小字，**位置与工具页的「共 n 个工具」完全一致**（右对齐、与标题底边对齐、同为 13px 次要文字）：

  > 搜索到「xx」相关工具共 n 个

  句中的数字用主文字色加重，便于扫读。n 来自服务端的 `total`。
- 页头小标签「Search」，标题「搜索结果」。
- 分类胶囊与工具页共用同一份数据、同一个选中态，**可与搜索词叠加**（先搜再按分类收窄）。
- 下方只展出筛选后的卡片（即工具页卡片的子集）。
- **同样分批加载**，卡片下方有与工具页同款的状态行（含失败态、重试，超时同样弹轻提示）。分页之下不可能一次拉全量，而且失败态需要有地方挂。
- **命中 0 个时不出任何卡片，也不出空状态块** —— 那行小字已经说明了数量（「共 0 个」），再叠一个空状态就成了两个「没有结果」。
- 注意与「取不到数据」区分：那是失败态，此时**连那行小字都不出现**。

## 七、搜索交互

- **提交式**：打字过程不触发跳转；按回车或点搜索框左侧的放大镜图标才提交。
- 输入为空提交 → 跳转 `/tools`（空输入不算一次搜索）。
- 地址栏是唯一真相来源。`?q=` 与 `?tag=` 都进地址栏；刷新、前进后退、分享链接都能还原到同样的结果。
- `Esc` 只清空输入框，不提交。
- 匹配范围：`name` / `description` / `tags`，全部小写化后包含匹配。**匹配由数据服务实现**，语义基准见 `docs/data-contract.md`；`q` 里的 `%` `_` 是普通字符，不是通配符。
- 输入框里打了字但没提交时，点分类胶囊**不会**把这段没提交的词算进去（结果只认地址栏里的 `q`）；居中那行小字会写明实际用的搜索词。

## 八、数据接口与工具本体（重要）

**工具数据不在前端代码里，也不在静态服务里。** 记录住在工作区根目录的 `catalog/`，由**另一个端口上的数据服务**读取并通过 HTTP 提供。

### 记录形状（`catalog/` 下每个 `.json` 一个工具）

```json
{
  "id": "ppt",
  "name": "PPT生成",
  "description": "根据主题快速生成演示文稿，适合汇报、课件和提案。",
  "tags": ["演示文稿", "办公"],
  "icon": "📊",
  "url": "",
  "enabled": true,
  "likes": 0,
  "order": 1000
}
```

- `id` / `name` 必填，缺任何一个这条记录会被丢弃并打一条服务端警告，其余工具不受影响。
- `url` 为空时点击不跳转，提示「即将上线」。**`url` 只接受 http/https，或站内以单个 `/` 开头的地址**（本地部署的工具就填 `/tools/<项目名>/`，见下）；其它协议（如 `javascript:`）与 `//evil.com` 这类协议相对地址一律归一化成空串 —— 数据离开代码之后，这是必须的防线。
- `enabled: false` 表示暂不展示。**筛选和计数都在服务端做，这个字段不会发给前端。**
- `likes` 是点赞数，非负整数，缺省 0。**首页热门推荐的排序依据**（降序，同数按 `order`、`id`）。
- `order` 越小越靠前，缺省 1000。**排序规则固定为 `order` 升序、同 `order` 按 `id` 升序** —— 排序必须确定，否则分页会重复和漏项。
- `catalog/_template.json` 是模板，文件名以下划线或点开头的会被跳过。

新增 / 删除 / 修改工具：**直接增删改 `catalog/` 下的文件即可，不需要重启任何服务**（数据源每次请求重新读目录），也不用改一行代码。

### 端点（数据服务，均 GET）

| 路径 | 说明 |
| --- | --- |
| `/api/tools?q=&tag=&page=&pageSize=` | 分页列表，服务端过滤。`pageSize` 默认 12、上限 60 |
| `/api/tags` | 分类清单，用得多在前、同次数按字典序升序 |
| `/api/hot?limit=6` | 首页热门：按 `likes` 降序、同数按 `order` / `id` 升序，取前 limit 个 |
| `/api/health` | 存活与数据源自检 |

参数非法**直接 400，不静默兜底**（兜底会让「地址写错了」表现成「结果莫名其妙」）。
拿不到数据返回 `500` 且 `code` 为 `DATA_SOURCE_UNAVAILABLE` —— **前端据此区分「0 条」和「不知道有几条」**。

完整的字段、上限、错误码与实测返回见 `docs/data-contract.md`。

### 只读（硬性）

**两个服务都没有任何写入接口，一个都没有。** 除 `GET` / `HEAD`（数据服务另有 `OPTIONS`）之外的一切方法一律 `405`，服务端代码里没有收请求体、也没有写盘的分支。

- **`likes` 是记录里的静态值**：读得到、算得出热门，但**不存在任何能让访客改它的入口**。首页那 6 张卡今天和明天是同一批，正是因为没人能从这个站上把它改掉。
- 点赞的写入路径是**将来的事**，且它一出生就要带自己的设计（谁能改、怎么防刷、要不要校验来源）—— 那是新做一套东西，不是在这里放宽一条限制。**在这套设计定下来之前，不放宽。**
- 这条同时是**离线的**：记录只能由维护者在本机改文件（见第十三节「运维备忘」）。浏览器侧根本摸不到 `catalog/` 与 `data-service/` —— 这是第三节那两张白名单自带的性质，不是额外加的规则。

### 数据源可替换

`DATA_SOURCE` 决定记录的存储方式，目前四个实现：`json-dir`（默认，读 `catalog/` 目录）、`json-file`（单个 json 文件）、`js-file`（单个 js 文件）、`mysql`（两张表，**完整实现但未实测**，接入前必须走验证清单）。

**归一化、匹配、排序、分页的语义只有一份**，住在 `data-service/core/`，不在适配器里 —— 否则不同数据源的结果迟早不一致。换数据源不改页面代码，也不改静态服务。见 `docs/adapters.md`。

**「用哪边的数据」必须是一个明确的、找得到的开关**，不能散在若干处靠推断：

| 想改什么 | 改哪里 |
| --- | --- |
| 用哪个适配器（清单文件 / MySQL / …） | `data-service/core/resolve.js` 的 `DEFAULT_SOURCE` |
| 清单文件放在哪 | `data-service/adapters/json-dir.js` 的 `DEFAULT_DIR` |

这两行在源码里用 ★ 标出来了，搜 `★` 就能找到。代码里的默认值是**能直接跑的**（现在是 `json-dir` 读 `catalog/`），所以「改成本地清单」和「改成数据库」都只是改这一行的事，不用读别的代码去猜；环境变量 `DATA_SOURCE` / `DATA_DIR` 优先级高于它们，跑临时组合时不必动源码。

### 工具本体 `tools/`（「货」）

`catalog/` 放的是**记录**（名字、描述、分类、点赞数），`tools/` 放的是**本体** ——
去 GitHub download zip、解压、把整个目录放进来。一个项目一个子目录，**目录名就是项目名**。

```
tools/<项目名>/index.html      ← 这个地址的入口，必须有
```

两边的对应关系靠记录的 `url` 字段牵起来：`url` 填 `/tools/<项目名>/`，卡片点开就走到托管。

**点击卡片之后的完整链路**：卡片把 `url` 写在 `data-tool-url` 上 →
点击时同步读出并 `window.open`（见第九节）→ 静态服务的 `/tools/<项目名>/` 托管把文件发出去。
`tools/<项目名>/` 不存在时，给的是**专门的提示页**「这个工具还没有本地副本」，不是笼统的 404
（见第三节）。这是「地址对、货没到」与「地址写错了」的区别。

页面在这条链路之前还多做一步：卡片渲染完就挨个探一次本体在不在，**明确不在的**卡片会被贴上角标，
点击时不再开一个注定是错误页的新窗口，就地给提示（见第五节与第九节）。这只是提前拦一道 ——
**拦不住的（探不到、或者记录后加的）仍然由服务端那张说明页兜底**，两道都要在。

`url` 结尾那个斜杠不能省，原因见第三节第 4 条。

**有意没做的部分**（依赖一个还没定的方案，定了再做；最后一条是**有意不开放**，不是同一回事）：

- 扫 `tools/` 自动生成 `catalog/` 记录 —— 现在两边手动对齐，靠 `url` 牵起来
- 每个项目里放清单文件声明名字、描述、分类
- 按项目装依赖、起进程、做构建 —— 也就是「真的把项目跑起来」
- **点赞数的写入路径**：现在 `likes` 是记录里的静态值，读得到、算得出热门，但没有「点一下 +1」的入口，也没有存的地方（见上「只读」一节 —— 这不是「还没来得及做」，是**有意不开放**）

真要做的时候，起作用的是已经铺好的两条接缝：数据侧的**适配器**（第八节上半）和静态侧的
**`/tools` 白名单**。页面代码一行不用动。

## 九、交互

- 页面跳转有明确选中状态（导航黑底白字）。
- 卡片 hover 轻微上浮 / 边框变化，不要夸张。
- 分类标签：胶囊样式，选中黑底白字，未选中白底灰边。
- 点击卡片分三种情形，**判断全部在同步调用栈里做完**：
  | 情形 | 结果 |
  | --- | --- |
  | `url` 为空（还没上线） | 不跳转，轻提示「即将上线」 |
  | 有 `url`，且卡片已探明**本地副本不在** | 不跳转，轻提示「还没有本地副本」 |
  | 其余（外链、站内地址、以及**探不到**） | 新窗口打开 |
  - **开窗必须在用户点击的同步调用栈里完成** —— 中间一旦有 `await`，浏览器会当成弹窗拦掉。这也是「本地副本在不在」必须**提前探好记在卡片上**的原因：到点击那一刻才去问服务端，就来不及了（见第五节）。
  - 明知打不开就不开：本地副本确实不在时，新窗口里只会是一张说明页，用户还得自己关掉，不如就地讲清楚。但只有**探明确实没有**才走这条；探不到的情况下照旧打开，让服务端去给结论 —— 页面不替服务端下结论。
  - `url` 可以是外链（`https://…`），也可以是**站内地址** `/tools/<项目名>/`（本地部署的工具本体）。两种在页面上完全一样，都是新窗口打开 —— 页面不需要知道工具是本地的还是外站的。

### 数据不可用时的表现（硬要求）

**核心区分：「0 条」与「不知道有几条」必须彻底分开。** 数据服务不可用时，**不许出现任何数字，也不许出现任何卡片（包括首页的虚线占位卡）**。

| 视图 | 元素 | 数据不可用 | 成功且 0 条 |
| --- | --- | --- | --- |
| 首页 | 热门网格 | 失败文案 + 重试（虚线框） | 「暂无工具收录」 |
| 首页 | 热门计数 | 空 | 「共 0 个」 |
| 工具页 | 分类筛选条 | 整条不渲染 | 正常（有分类的话） |
| 工具页 | 计数 | 空 | 「共 0 个工具」 |
| 工具页 | 卡片网格 | 空 | 空状态块「没有匹配的工具」 |
| 工具页 | 状态行 | 失败文案 + 重试 | 空 |
| 搜索页 | 计数 / 网格 / 状态行 | 空 / 空 / 失败文案 + 重试 | 「共 0 个」/ 空 / 空 |

- 失败文案是**两个常量**（连不上、超时各一句），三处共用，避免措辞漂移。**区分两者不是修辞**：连不上是「服务没起来」，超时是「服务起来了但不应答」，要查的东西不一样。
- 请求必须带**超时**：服务被关掉是秒失败，但服务**卡住**不会 —— 没有超时，页面就永远停在「正在加载工具……」，既不报错也没有重试入口。
  - 超时的时间上限写死在 `assets/js/api.js` 顶部：取数 5 秒，本地副本探查 2.5 秒（探查只是给卡片加个角标，不值得让它挂 5 秒）。
  - **超时的响应必须丢掉**：超时一到就中止请求，对面后来才回的那份数据根本到不了页面 —— 不是靠调用方记得判断，而是让它收不到。同一层还有一道针对「成功但已经过期」的响应（筛选条件变了之后的旧响应）的闸，两道都必要。
  - 超时还会**额外弹一条轻提示**：状态行上那行小字说不清是哪一种失败，弹一下更直接。
- **页面外壳（Hero、标题、导航选中态、`document.title`）从地址栏同步渲染，不等数据** —— 数据服务全挂时页面依然完整，只是没有工具。
- 失败后点重试要能从**正确的位置**继续，不是从头再来。
- **深链里的分类在数据不可用时不许被清掉**：只有分类清单**真的取到了**，才谈得上「地址里这个分类存不存在」。否则数据服务一挂，`/tools?tag=办公` 会被静默清成「全部」，页面和地址栏就对不上了 —— 那是拿「没数据」冒充「没这个分类」。清单到手后再补做这次校验。

## 十、服务器与访问配置（预留接口，方便改 IP）

**两个服务、两个端口**，都不写死。静态页一个端口，数据服务另一个端口；两者互不连接，静态服务只把数据服务的地址告诉浏览器（见 `docs/architecture.md`）。

| 服务 | 变量 | 默认 |
| --- | --- | --- |
| 静态 | `HOST` / `PORT` | `127.0.0.1` / `3000` |
| 静态 | `DATA_ORIGIN` | `http://127.0.0.1:3001`（告诉前端数据服务在哪） |
| 数据 | `DATA_HOST` / `DATA_PORT` | `127.0.0.1` / `3001` |
| 数据 | `CORS_ORIGIN` | 未设 → `*`（逗号分隔的白名单） |
| 数据 | `DATA_SOURCE` | `json-dir` |
| 数据 | `DATA_DIR` / `DATA_FILE` | `catalog` / — |

- **一条命令起两个**：`npm start`。它会按 `DATA_HOST`/`DATA_PORT` 算出数据服务地址传给静态服务，所以 **`DATA_PORT=4001 npm start` 改一处，两个服务一起跟上**，前端一行不改。任一服务退出，另一个也会停。
- **不想开终端就双击**：根目录的 `start.cmd`。它只是 `scripts/start.js` 外面一层「双击得动」的壳，不重复任何配置。**关掉那个窗口就是停掉两个服务** —— 两个服务是那个控制台的子进程，窗口一关系统会把它们一起收掉，所以不用手动去杀进程。Ctrl+C 同样有效。
- 单独启动的能力完整保留：`npm run start:static`、`npm run start:data`（以及备选命令 `HOST=127.0.0.1 PORT=3000 node server.js`）。
- 启动后控制台打印访问地址，**两个服务的地址都打**。
- `/api/config` 只读接口返回 `{ host, port, url, data: { origin } }`。前三个字段供页脚显示访问地址（**不要把地址写死在页面里**），`data.origin` 供前端定位数据服务。
  - 前端解析数据服务地址的优先级：`<meta name="data-origin">` → `/api/config` 的 `data.origin` → `location.origin`（同源反向代理时自动正确）→ 都没有则进入「数据不可用」态。`file://` 直接走最后一条。
  - **`/api/config` 一次加载只许问一遍**：页脚和取数前的地址解析都要用它，两处几乎同时发起。前端要做的两层（在途合并 + 成功缓存、失败不留缓存）写在 `assets/js/api.js` 的 `fetchConfig` 上，改那里时别把缓存拆掉 —— 拆了就变回一次加载发两遍。
  - 每次请求都带超时（取数 5 秒、本地副本探查 2.5 秒，见第九节），超时用 `AbortSignal` **掐断**而不是「回来之后不采用」。
- **两个服务都是只读的**：除 `GET` / `HEAD`（数据服务另有 `OPTIONS`）外一律 `405`，没有任何写入接口，也没有收请求体或写盘的代码（见第八节「只读」）。
- **两个服务都设了连接层上限**（收请求头 10 秒、收完整个请求 20 秒、空闲长连接 5 秒）。这不是性能优化，是防止「一个不发完请求的连接白占着 socket」—— 那种故障表现成「服务在跑，但有的请求一直不回来」，最难查。它和前端那个 5 秒超时是**两道独立的闸**：前端管「我不等了」，服务端管「你别占着我的连接」。
- **前端只发「简单请求」**（只用 GET、不带自定义头、不带凭据），因此不触发 CORS 预检。要加请求头或改凭据之前，必须先确认数据服务的 CORS 配置。
- 备选启动命令 `python3 -m http.server 3000 --bind 127.0.0.1` 仍然可用，但它**只托管静态文件、没有 `/api/config` 也没有数据服务**，所以页面会进入「数据不可用」态（显示失败文案 + 重试）。这是预期表现，不是坏了。

### `file://` 直开

以 `file://` 直接打开 `index.html` **现在看不到任何工具** —— ES module 在 `file://` 下不执行，页面什么都不渲染。这是有意的，代价是换掉了「双击 HTML 就能看」的旧行为。

## 十二、文案与扩展性约束（重要）

这个项目会持续加页面、加工具，所以任何**写死当前规模或当前状态**的说法都不许进页面 —— 一加东西它就变成假话。

- **不写会过期的说法**：不写「本站只有 N 个页面」「目前只有…」，不写「持续收录中」「初版」这类进度标签，也不写「在 `TOOLS` 数组中添加第一项后…」这种对访客讲内部实现的句子。（已按此清理：404 页的页面数量说明、页脚的「持续收录中」、首页小标签的「初版」、工具页描述里的实现说明、热门区空状态的开发提示。）
- **页面文案只描述长期成立的事**：这个站是干什么的、这一页能做什么。给维护者看的说明留在代码注释和本文档里。
  - 例外是**渲染当刻成立的状态**，如工具页与搜索页的「正在加载工具……」「正在加载更多工具中……」「已加载全部工具」（见第五节）—— 它们说的是这一瞬间列表还有没有没加载的，不声称任何规模或进度，所以不会过期，不要当成陈旧文案删掉。
- **数据不可用时不得展出任何卡片，也不得显示任何计数** —— 「0」与「未知」必须可区分。虚线占位卡只能是**成功拿到数据**的结果（表示「不足 6 个」），绝不能是**拿不到数据**的兜底（那会变成「本站工具不足 6 个」的假话）。详见第九节那张对照表。
- **「不知道」一律不许当成「没有」** —— 这条比上面那条更宽，凡是「没取到」的地方都适用：拿不到数据不是「0 条」，**探不到本地副本不是「本地副本不在」**（见第五节）。两者的区别不在措辞，在**有没有替对方下结论**：数据不可用时页面不下结论（不下卡片、不出数字），探查失败时页面也不下结论（不贴角标、照旧打开）。
- **两个服务只读，这是硬性的**：不给访客任何能改数据的能力 —— 没有写入接口，除 `GET` / `HEAD` 外一律 `405`。`likes` 是记录里的静态值，谁能改它这件事现在没有答案，**在没有答案之前不放宽任何一条**（见第八节「只读」）。将来做点赞，那是一套要单独设计的东西（谁能改、怎么防刷、要不要校验来源），不是在这里开一个口子。
- **结构性的东西从数据推导，不手写死**：
  - 分类胶囊由分类清单推导；
  - 404 页的出口链接由 `ROUTES` 派生 —— **新增页面只在 `ROUTES` 里加一行**，路由匹配和 404 页的出口都会自动跟上。`nav: null` 表示该页面必须带参数才有意义（如 `/search`），不列进 404 页的出口。
- 路由表用 `hasOwnProperty` 判定命中：`ROUTES` 是普通对象，`/constructor`、`/toString` 这类路径会顺着原型链取到真值，不判就是 500。

## 十三、项目管理与文档

`Readme.md` 是**需求**（这个站应该是什么样），各目录下的 `README.md` 与 `docs/` 是**设计**（怎么做到的）。**两者冲突时以 Readme 为准。**

### 文档分两级

**第一级：每个目录自己那份 `README.md`** —— 讲「这个目录是干什么的、和谁配合」。

| 目录 | 那份 README 讲什么 |
| --- | --- |
| `assets/README.md` | 六个 js 文件各管什么、样式为什么分两处写、几个容易踩的坑 |
| `catalog/README.md` | 工具**记录**的字段与增删步骤（「货架上的标签」） |
| `tools/README.md` | 本地工具**本体**、点击卡片之后的完整链路（「货」） |
| `data-service/README.md` | `core/` 与 `adapters/` 的分工、一次请求经过什么 |
| `scripts/README.md` | 一条命令起两个服务、端口为什么只在一处配 |
| `docs/README.md` | 五份设计文档的导航与改动流程 |

**第二级：`docs/` 下五份** —— 讲跨目录的设计决定。

| 文档 | 职责 |
| --- | --- |
| `docs/principles.md` | **设计原则**：遇到新问题时的判断规则（网络出口、超时、缓存、验证方法…） |
| `docs/architecture.md` | 三层结构、数据流、端口与 CORS、语义为什么住在 `core/`、三张白名单 |
| `docs/data-contract.md` | 端点 / 参数 / 响应 / 错误码 / 记录形状。**前后端唯一契约** |
| `docs/adapters.md` | 适配器契约、四个实现、MySQL 接入步骤与验证清单 |
| `docs/changelog.md` | 按次记录改动，含「同步了 Readme 哪几节」 |

**改动之前先扫一眼 `docs/principles.md`** —— 那几条是拿主意用的，不是背景知识。
它只收**反复用得上、且不写下来就会被忘掉**的判断规则；实现细节留在代码注释里，一次性的决定留在 changelog 里。

`docs/data-contract.md`、`data-service/core/contract.js`、`data-service/core/normalize.js`
是同一份契约的三种形式，**改一处必须同时改另外两处**。

### 改动流程

1. 改代码。
2. 同步 `Readme.md` 里对应的那一节 —— 实现变了文档没变，下一轮改动的依据就是错的。
3. 动了某个目录的**结构或职责**，同步那个目录自己的 `README.md`。
4. 契约相关的改动，同步 `docs/data-contract.md` 与 `core/contract.js`、`core/normalize.js`。
5. 在 `docs/changelog.md` 追加一条，写清这次改了什么、同步了 Readme 哪几节。

### 版本控制

仓库在 GitHub 上（公开）。**远端只是备份与分享，站点不跑在上面** —— GitHub Pages 只能发静态文件，跑不了 `data-service/` 这个 Node 进程，所以那个网址打开只会看到设计好的「数据不可用」态。这不是坏了，是它本来就不该那样用（详见 `docs/principles.md` 第一条那条判断：功能性的依赖不能这么办）。

- **换行符由 `.gitattributes` 保证，不靠谁的全局设置**。这台机器的 git 全局是 `core.autocrlf=true`（检出时统统转 CRLF），和本项目「除批处理外一律 LF」正好相反 —— `.gitattributes` 的优先级更高，那几行写完，这个仓库就不受全局设置影响了，`start.cmd` 在任何机器上 clone 下来都还是 CRLF。
- **`.gitignore` 里有 `.env`**，这条一直留着：将来真接数据库时很容易顺手写一个 `.env`，而它里面有密码，仓库是公开的。
- **临时脚本放系统 temp，不要放项目目录里** —— `.gitignore` 是事后补网，不如一开始就别放进来。
- **根目录那份文档只能叫 `Readme.md` 这一个名字，不许再出现一个 `README.md`**。Windows 与 macOS 不区分文件名大小写，两个名字同时进仓库，会让这个仓库**在那类机器上根本没法检出**。本项目已经踩过一次：GitHub 建仓时自动生成的 `README.md` 和本地 `Readme.md` 撞名，合并时把本地文档覆盖成了两行模板（内容没丢，在 git 历史里，但当时磁盘上那份已经没了）。各子目录里的 `README.md`（`docs/`、`assets/` 等）不受影响 —— 它们各自目录下没有同名冲突。

### 运维备忘

- 加一个工具（**记录**）= 在 `catalog/` 下加一个 json，**不用重启**，刷新页面即可。
- 加一个本地工具（**本体**）= 把项目解压到 `tools/<项目名>/`，再把记录里的 `url` 填成 `/tools/<项目名>/`。同样不用重启。
- 启动 = 双击根目录 `start.cmd`，或 `npm start`。**关掉那个窗口两个服务就一起停了**，不用手动杀进程。
- 换端口 = 改环境变量（见第十节）。
- 换数据源 = 改 `data-service/core/resolve.js` 里的 `DEFAULT_SOURCE`（搜 `★`），或临时用 `DATA_SOURCE=` 覆盖（见第八节那张表）。
- **改 `start.cmd` 时注意换行符必须是 `CRLF`**。它是批处理文件，LF 换行会让 cmd.exe 的解析器在多字节字符处丢失同步，症状是注释行被从中间截断、当成命令去执行。这个坑踩过一次，记在 `docs/changelog.md`。根目录的 `.editorconfig` 已经把 `*.cmd` / `*.bat` 固定成 CRLF —— 编辑器遵守它就不会再踩，但**用不认 `.editorconfig` 的工具写文件时要自己确认**。
- 端口占着不放时，**按 PID 精确终止**：

  ```bash
  netstat -ano | grep -E "127.0.0.1:(3000|3001).*LISTENING"   # 最后一列是 PID
  taskkill //F //PID <那个 PID>
  ```

  不要用 `taskkill /F /IM node.exe` —— 那会杀掉机器上所有 node 进程，包括别人的。
