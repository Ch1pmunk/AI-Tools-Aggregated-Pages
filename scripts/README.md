# scripts/ —— 启动脚本

```
scripts/start.js     一条命令起两个服务
```

```bash
npm start                        # 静态页 :3000 + 数据服务 :3001
PORT=8080 npm start              # 静态页换端口
DATA_PORT=4001 npm start         # 数据服务换端口，页面自动跟上
```

不想开终端的话，**双击根目录的 `../start.cmd`** 也行。那只是本文件外面一层壳
（`cd` 到自己所在目录 → `node scripts\start.js`），**不重复任何配置** ——
端口的推导仍然只在本文件里发生一次。关掉那个窗口两个服务就一起停。

> `../start.cmd` 是**批处理文件，换行符必须是 `CRLF`**。LF 换行会让 cmd.exe
> 的解析器在多字节字符处丢失同步，把注释行从中间截断当成命令执行。
> 这个坑真的踩过一次，过程和症状记在 `../docs/changelog.md`。

## 一、它存在的理由只有一个：**端口只在一处配**

静态服务要告诉浏览器「数据服务在哪个地址」（页面靠 `/api/config` 的 `data.origin` 拿它）。
这个地址由本脚本从 `DATA_HOST` / `DATA_PORT` **推导**出来再传给静态服务：

```
DATA_PORT=4001
   ├─▶ 数据服务监听 4001
   └─▶ 静态服务的 DATA_ORIGIN = http://127.0.0.1:4001
                                  └─▶ /api/config → data.origin → 页面据此取数
```

所以改数据服务的端口只需要改一个环境变量，**不会出现「数据服务搬走了、页面还在敲老地址」**
—— 那是这类双服务结构最容易踩、又最难查的一种错：页面全空，但两个服务看起来都在跑。

`DATA_ORIGIN` 也可以显式指定（数据服务在另一台机器上时就该显式指定），显式值优先。

## 二、行为

| 行为 | 为什么 |
| --- | --- |
| `stdio: 'inherit'` | 两个服务的日志打在同一个终端里，不加前缀、不重定向 —— 排障时一眼能顺下来。**顺带买到一件事：两个子进程共用启动者的控制台，所以关掉那个窗口它们会一起被系统收掉**（`../start.cmd` 靠的就是这个）。反过来说，**别给子进程加 `detached: true`** —— 加了就是「关了窗口进程还在」，而这个脚本的整个使用方式都建立在「关窗即停」上 |
| **任一子进程退出，另一个也停掉** | 页面没数据、或数据没人看，留着都没意义 |
| 收到 `SIGINT` / `SIGTERM` 先转发给子进程，再等它们收尾，超时就直接退 | 不留孤儿进程、不留占端口 |
| 先起数据服务，再起静态页 | 顺序其实无所谓（页面加载时才取数），只是日志按这个顺序读起来更顺 |
| 把 `0.0.0.0` 换写成 `127.0.0.1` 再给浏览器 | 绑 `0.0.0.0` 是「监听所有网卡」，不是「访问 0.0.0.0」，照原样写进页脚和地址栏都是错的 |

## 三、单独启动的能力完整保留

本脚本只是把两件事按正确顺序拼起来，不做任何别的加工。所以下面这些照旧可用：

```bash
npm run start:static        # 只起静态页（页面会显示「未能读取工具数据」，这是预期表现）
npm run start:data          # 只起数据服务（可以单独 curl 它）
HOST=127.0.0.1 PORT=3000 node server.js
```

只起静态页时页面进入「数据不可用」态 —— 那正是 `Readme.md` 第九节要求的表现，
不是坏了。**这也是验证「数据不可用时不画任何卡片、不显示任何计数」最方便的办法。**

## 四、Windows 上的一点实情

`Ctrl+C` 会把事件发给整个控制台进程组，两个子进程都收得到，正常退出。

而用 `taskkill /F` 硬杀父进程时，Windows 不保证级联 —— 本机实测两个子进程会一起消失、
端口全部释放，但这是操作系统行为，不是本脚本能保证的。真出现端口占着不放：

```bash
netstat -ano | grep -E "127.0.0.1:(3000|3001).*LISTENING"   # 最后一列是 PID
taskkill //F //PID <那个 PID>
```

**别用 `taskkill /F /IM node.exe`** —— 那会杀掉机器上所有 node 进程，包括别人的。
